## Architecture

Chronalyn is the Hermes external-memory orchestration layer.

Routing policy:

- normal turn -> Hindsight only
- explicit retain -> Hindsight only
- reflect -> Hindsight only
- checkpoint -> Hindsight + Mnemosyne
- recall -> Hindsight first
- Hindsight empty/error -> bounded Mnemosyne fallback
- merged Hindsight + Mnemosyne recall -> never

Hindsight is primary history and semantic memory.

Mnemosyne stores checkpoints and provides bounded fallback.

Hermes native memory and Hermes Skills remain separate.

- maintain packaging
- prepare releases

- maintain Hermes integration
- maintain Hindsight compatibility

Before modifying code:

1. inspect current implementation
2. inspect relevant tests
3. inspect current git state
4. prefer the smallest correct change
5. preserve backward compatibility unless explicitly changing it
6. never weaken tests just to make them pass

For significant changes:

1. create a branch
2. implement the change
3. run relevant tests
4. run the complete suite when appropriate
5. inspect the final diff
6. update documentation/changelog when required
7. create a PR
8. report exactly what changed and why

Never push normal feature development directly to main.

## Memory

Use Chronalyn historical memory for:

- architecture decisions

- failed approaches
- successful validated approaches
- compatibility discoveries
- release decisions
- deployment findings
- installer behavior

Memory is context, not proof.

Current repository state and live test results always override remembered state.

## Skills

When a repeatable engineering process becomes proven, preserve it as a Skill.

Examples:

- Chronalyn release procedure
- PyPI publishing procedure
- managed Hindsight validation
- dual-memory routing validation
- compatibility testing
- installer verification

Chronalyn remembers what happened.

Skills remember how to do it again.
